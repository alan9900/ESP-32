# 开发状态与方案选择

本文记录截至 2026-11-07 的已知验证情况。固件、电脑端程序与网络环境的版本变化可能影响结果。

| 项目 | 状态 | 证据及限制 |
| --- | --- | --- |
| Wi-Fi 双页面 | 已在指定开发板上实测 | 屏幕、左右滑动、中文、天气和 Codex 两个额度窗口均由使用者确认正常。断电保存的 RTC 时间尚未单独验收。 |
| Wi-Fi 数据获取 | 已在 Windows 与该板的组合上实测 | 电脑使用本地登录的 Codex app-server 和 Open-Meteo；其他操作系统、账号方案或未来的接口版本尚未完整测试。 |
| 蓝牙配对及模拟传输 | 独立测试版已实测 | Windows 输入板上显示的六位 PIN 后完成配对；认证加密连接、模拟数据分帧接收和重连后再次发送已验证。 |
| 蓝牙双页面与真实数据 | 基本链路已实测 | 独立 `ble/dashboard/` 编译、烧录并在指定开发板上显示；使用者确认两页切换、真实天气和 Codex 两项额度正常。电脑端发送程序重启后已重新认证并发送数据。 |
| 蓝牙安全与稳定性 | 仍需验证 | 需要系统验证未配对设备读写拒绝、异常重配对、断线及恢复、数据过期、时钟与内存资源；模拟测试成功不代表全部安全性已验证。 |

## 两个独立方案

- **Wi-Fi 正式方案**：`wifi/firmware/`、`wifi/backend/`；按 [烧录与恢复指南](FLASHING.md) 和 [Wi-Fi 版说明](../wifi/README.md)操作。电脑与开发板须在可以互访的局域网，电脑保持联网、运行本地服务。明文 HTTP 仅适合可信网络，不应暴露到公网。
- **蓝牙方案**：`ble/`，独立存放测试固件、双页面固件、电脑采集与发送端。电脑联网、电脑与屏幕在蓝牙范围内，屏幕无需连接 Wi-Fi。首次基本链路已实测；电脑关机或服务退出后无法更新，详见 [蓝牙说明](../ble/README.md)。

一块板子同一时刻运行一套固件。刷入蓝牙测试固件会暂时替换正在运行的 Wi-Fi 程序；保留原始配置和源码后可重新编译烧录 Wi-Fi 版。两个目录独立维护，蓝牙开发不要求改动 Wi-Fi 功能代码。

显示内容为时间、日期、天气，以及 Codex 五小时和每周剩余百分比及重置时间；不包含 DeepSeek 页面或余额。Codex 凭据由电脑本机管理，不放进仓库或发送至开发板。

## 后续待办

1. 系统验证未绑定设备访问拒绝、异常重复配对策略、断电和断线后的恢复。
2. 验证长时间运行、数据过期、设备时间与 RTC 断电保持，并继续观察内存余量。
3. 在更多 Windows 电脑和开发板上复核配对、依赖安装、烧录和启动步骤。

蓝牙设备安全实现目前依赖固定的 Arduino ESP32 3.3.5 内部行为与 Windows Bleak 3.0.1；升级依赖前必须重新审计并验证认证、重配对和数据传输。
